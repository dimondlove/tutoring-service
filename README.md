# РепетиторПлюс

Веб-приложение для поиска репетиторов и записи на занятия. Проект объединяет пользовательский интерфейс, REST API и реляционную базу данных. Frontend раздаётся через Nginx, серверная часть реализована на Java и Spring Boot, данные хранятся в PostgreSQL.

## Возможности

### Публичная часть

- просмотр каталога репетиторов;
- просмотр предметов, специализации, опыта, рейтинга и стоимости занятий;
- поиск и фильтрация каталога;
- просмотр доступных временных слотов;
- регистрация ученика и вход по электронной почте и паролю.

### Работа с занятиями

- создание бронирования на доступный временной слот;
- бесплатное вводное занятие;
- подтверждение или отклонение заявки репетитором;
- отмена занятия в рамках правил backend;
- просмотр предстоящих и прошедших занятий;
- сохранение статуса занятия и отображение его в личных кабинетах;
- домашние задания и оценки в рамках поддерживаемых API-операций;
- защита от конфликтующих бронирований на уровне серверной логики и PostgreSQL.

### Кабинет ученика

- просмотр личных данных;
- просмотр предстоящих занятий;
- просмотр истории занятий;
- отмена доступной для отмены записи;
- оценка завершённого занятия.

### Кабинет репетитора

- просмотр и редактирование профиля;
- управление предметами и стоимостью занятий;
- настройка рабочих часов и выходных;
- просмотр занятий и заявок;
- принятие и отклонение заявок;
- добавление домашнего задания;
- оценка ученика.

### Административная панель

- просмотр статистики по пользователям и бронированиям;
- поиск пользователей;
- блокировка и разблокировка пользователей;
- просмотр и активация/отключение профилей репетиторов;
- создание профиля репетитора на основе существующего пользователя;
- управление справочником предметов;
- просмотр общего расписания и бронирований;
- отмена бронирования администратором.

## Роли пользователей

| Роль | Основные возможности |
|---|---|
| Гость | Просмотр каталога, поиск репетиторов и доступных слотов |
| Ученик (`STUDENT`) | Бронирование и отмена занятий, личный кабинет, история и оценки |
| Репетитор (`TUTOR`) | Профиль, предметы, цены, рабочее расписание, заявки, занятия и домашние задания |
| Администратор (`ADMIN`) | Статистика, пользователи, профили репетиторов, предметы и общее расписание |

## Архитектура

Приложение запускается как три сервиса Docker Compose:

```text
Браузер пользователя
        |
        v
Nginx (Frontend, порт 3000)
        |                       \
        | HTML / CSS / JS         \ запросы /api/*
        |                         \
        v                          v
Пользовательский интерфейс    Spring Boot REST API (порт 8080)
                                      |
                                      | SQL / JPA
                                      v
                               PostgreSQL 16 (порт 5432)
```

Браузер открывает сайт по адресу `http://localhost:3000`. Nginx отдаёт статические файлы из папки `frontend` и перенаправляет запросы с префиксом `/api/` на backend. Frontend не подключается к PostgreSQL напрямую: доступ к базе данных выполняет только Spring Boot.

Для защищённых запросов frontend передаёт JWT в заголовке `Authorization: Bearer <token>`. Токен и краткая информация о текущем пользователе сохраняются в `localStorage` браузера для поддержания авторизованной сессии. Рабочие данные каталога, расписания, пользователей и бронирований запрашиваются у backend.

## Технологии

| Уровень | Технологии |
|---|---|
| Frontend | HTML5, CSS3, JavaScript |
| Web-сервер | Nginx (`nginx:alpine`) |
| Backend | Java 21, Spring Boot 4.1.2, Spring Security, Spring Data JPA |
| Авторизация | JWT, BCrypt |
| База данных | PostgreSQL 16 |
| Миграции БД | Flyway |
| Сборка backend | Gradle 9.8.2 |
| Контейнеризация | Docker, Docker Compose |
| Документация API | Springdoc / Swagger UI |
| Тестирование | JUnit 5, Mockito, Testcontainers |

В Dockerfile для сборки backend используется образ `gradle:9.8.2-jdk21-ubi9`, в котором Gradle уже установлен. Это позволяет не скачивать Gradle Wrapper с `services.gradle.org` во время сборки Docker-образа. Для локального запуска через `gradlew` Wrapper остаётся доступен и настроен на повторные попытки скачивания.

## Требования

Для обычного запуска всего приложения необходимы:

- Windows 10/11, Linux или macOS;
- Docker Desktop (Windows/macOS) либо Docker Engine с Docker Compose (Linux);
- доступ к интернету при первой сборке для загрузки Docker-образов и зависимостей;
- Git — если проект клонируется из GitHub.

Устанавливать Java и PostgreSQL отдельно для запуска через Docker Compose не требуется: они работают внутри контейнеров.

## Быстрый запуск

Все команды ниже выполняются из корневой папки проекта — той, в которой находятся `docker-compose.yml` и `.env.example`.

### 1. Получить проект

Если проект уже находится на компьютере, откройте его корневую папку в терминале IntelliJ IDEA или PowerShell.

Для клонирования из GitHub:

```bash
git clone <URL-репозитория>
cd <папка-проекта>
```

### 2. Создать файл `.env`

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

Файл `.env` содержит настройки подключения к PostgreSQL и секрет JWT. Он исключён из Git через `.gitignore`; не добавляйте его в коммиты и не публикуйте секреты.

### 3. Запустить приложение

При первом запуске выполните сборку и запуск всех сервисов:

```powershell
docker compose up --build -d
```

В Linux/macOS используется та же команда:

```bash
docker compose up --build -d
```

Docker Compose:

1. запускает PostgreSQL;
2. ожидает, пока проверка готовности базы данных пройдёт успешно;
3. собирает и запускает Spring Boot backend;
4. запускает Nginx и публикует frontend.

Первый запуск может занять больше времени, так как Docker загружает базовые образы и зависимости.

### 4. Проверить контейнеры

```powershell
docker compose ps
```

Ожидаются три сервиса со статусом `Up`; у базы данных дополнительно должен отображаться статус `healthy`.

### 5. Открыть сайт

Откройте в браузере:

**http://localhost:3000**

Для обычного последующего запуска, когда образы уже собраны, достаточно:

```powershell
docker compose up -d
```

## Настройка окружения

Пример `.env.example`:

```dotenv
DB_NAME=tutoring
DB_USER=tutoring
DB_PASSWORD=tutoring
JWT_SECRET=local-dev-secret-local-dev-secret-0123456789
```

Описание переменных:

| Переменная | Назначение |
|---|---|
| `DB_NAME` | Имя базы данных PostgreSQL |
| `DB_USER` | Пользователь PostgreSQL |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL |
| `JWT_SECRET` | Секрет для подписи JWT; не короче 32 символов |

Значения из `.env.example` предназначены только для локальной разработки и демонстрации. Для размещения в открытой или производственной среде задайте собственные надёжные значения, не храните их в репозитории и не используйте демонстрационные пароли.

## Как проверить работу приложения

### Проверка состояния backend

Откройте:

```text
http://localhost:8080/actuator/health
```

При успешном запуске ответ содержит `"status":"UP"`.

### Проверка API через единый адрес frontend

В Windows PowerShell:

```powershell
Invoke-RestMethod http://localhost:3000/api/subjects
Invoke-RestMethod http://localhost:3000/api/tutors
```

Оба запроса должны вернуть JSON с предметами и репетиторами. Это также проверяет, что Nginx передаёт `/api/` запросы backend.

### Проверка пользовательского сценария

1. Откройте `http://localhost:3000`.
2. Зарегистрируйте нового ученика или войдите под `student@demo.com`.
3. Выберите репетитора, предмет и свободный временной слот.
4. Создайте бронирование.
5. Выйдите из аккаунта ученика и войдите под соответствующим репетитором. Например, Дмитрий Орлов: `tutor2@demo.com` / `Tutor123!`.
6. Откройте кабинет репетитора и подтвердите заявку.
7. Снова войдите под учеником и проверьте изменение статуса занятия.
8. При необходимости отмените запись и проверьте её в истории занятий.
9. Войдите как администратор и проверьте статистику, пользователей, профили репетиторов, предметы и общий список бронирований.

Этот основной сценарий был вручную пройден на локальном экземпляре проекта: регистрация и вход ученика, создание бронирования, вход под Дмитрием Орловым, подтверждение записи, отображение статуса в кабинете ученика, отмена и отображение отменённой записи в истории и административном расписании.

### Swagger UI

Откройте [Swagger UI](http://localhost:8080/swagger-ui/index.html). В документации можно просматривать доступные методы и выполнять запросы. Для защищённых методов сначала выполните `POST /api/auth/login`, скопируйте полученный JWT и используйте кнопку **Authorize**.

## Основные API-маршруты

## Управление Docker

Все команды выполняются из корня проекта.

**Посмотреть состояние контейнеров:**

```powershell
docker compose ps
```

**Посмотреть логи backend:**

```powershell
docker compose logs --tail=100 backend
```

**Следить за логами backend в реальном времени:**

```powershell
docker compose logs -f backend
```

**Посмотреть логи всех сервисов:**

```powershell
docker compose logs -f
```

**Пересобрать и перезапустить после изменения backend или Docker-конфигурации:**

```powershell
docker compose up --build -d
```

**Остановить контейнеры, сохранив данные PostgreSQL:**

```powershell
docker compose down
```

**Запустить ранее собранные контейнеры снова:**

```powershell
docker compose up -d
```

Файлы frontend подключены к контейнеру Nginx как read-only volume. После изменения HTML/CSS/JS обычно достаточно обновить страницу браузера с очисткой кэша (`Ctrl + Shift + R`). Пересборка backend при изменении только frontend не требуется.

### Сброс демонстрационной базы

Команда ниже удаляет Docker volume PostgreSQL вместе со всеми пользовательскими данными, бронированиями и изменениями. Используйте её только если действительно хотите начать с чистой базы:

```powershell
docker compose down -v
docker compose up --build -d
```

**Не выполняйте `docker compose down -v` для обычной остановки проекта.** Для обычной остановки используйте `docker compose down`.

## Резервное копирование базы данных

В папке `scripts` находятся скрипты `backup.sh` и `restore.sh`. Они рассчитаны на Bash (например, Linux, WSL или Git Bash) и используют параметры из `.env`. Перед запуском контейнер `db` должен быть активен.

**Создать резервную копию:**

```bash
bash ./scripts/backup.sh
```

Файл дампа сохраняется в папку `backups/`.

**Восстановить базу из дампа:**

```bash
bash ./scripts/restore.sh backups/<имя-файла>.dump
```

Восстановление выполняется с очисткой существующих объектов базы (`--clean --if-exists`). Используйте его внимательно: текущие данные могут быть заменены содержимым дампа. Храните резервные копии в безопасном месте и не добавляйте дампы с персональными данными в публичный репозиторий.

### Сквозная проверка API

В репозитории есть PowerShell-скрипт `scripts/api-check.ps1`. Он проверяет основные API-сценарии, права доступа и защиту от конкурентного бронирования. Скрипт рассчитан на демонстрационное наполнение базы и соответствующие тестовые аккаунты.

Запуск из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\api-check.ps1
```

Можно указать другой адрес backend и количество параллельных запросов:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\api-check.ps1 -Base "http://localhost:8080" -Racers 8
```

**Внимание:** скрипт создаёт вспомогательных тестовых пользователей, тестовый предмет и временные бронирования. Часть временных бронирований отменяется в ходе проверки, но тестовые пользователи остаются в базе. Запускайте скрипт на отдельной тестовой базе или после резервного копирования данных.

## Локальный запуск Backend без Docker

Этот режим предназначен для разработки и требует JDK 21 и доступного экземпляра PostgreSQL.

1. Поднимите базу данных. Например, из корня проекта можно запустить только сервис БД:

   ```powershell
   docker compose up -d db
   ```

2. Создайте `.env` и задайте переменные подключения к БД и `JWT_SECRET`.
3. Перейдите в каталог backend:

   ```powershell
   cd backend\tutoring-backend
   ```

4. Укажите переменные окружения и запустите Spring Boot:

   ```powershell
   $env:SPRING_DATASOURCE_URL = "jdbc:postgresql://localhost:5432/tutoring"
   $env:SPRING_DATASOURCE_USERNAME = "tutoring"
   $env:SPRING_DATASOURCE_PASSWORD = "tutoring"
   $env:JWT_SECRET = "local-dev-secret-local-dev-secret-0123456789"
   $env:SPRING_PROFILES_ACTIVE = "demo"
   .\gradlew.bat bootRun
   ```

При таком способе запуска frontend отдельно раздаётся локальным веб-сервером. Рекомендуемый и наиболее простой вариант запуска всего приложения — Docker Compose.

## Ограничения текущей версии

В текущем backend отсутствуют API-методы для следующих функций, поэтому они не считаются завершёнными в интеграции:

- отправка и модерация жалоб пользователей;
- загрузка фотографий с сохранением файлов на сервере;
- отдельный реестр образования, дипломов и сертификатов репетитора.

Публичная регистрация создаёт ученика. Создание профиля репетитора выполняется администратором на основе существующего пользователя. Для промышленного использования также необходимо заменить демонстрационные секреты и пароли, настроить HTTPS, резервное копирование, политику хранения персональных данных и подходящую инфраструктуру.

Не все дополнительные функции (например, изменение рабочего расписания, управление ценами, домашние задания и выставление оценок) проходили отдельный ручной сценарий в рамках первоначальной проверки интеграции. Их следует проверить перед выпуском новой версии.

## Для разработчиков

Перед коммитом проверьте, что в Git не попали:

- `.env` и любые файлы с реальными секретами;
- дампы PostgreSQL с пользовательскими данными;
- локальные каталоги `.idea`, `.gradle`, `build` и временные файлы IDE.

Для командной работы создавайте отдельную ветку, отправляйте изменения через Push и открывайте Pull Request в основную ветку репозитория.
