# Tutoring Service

Веб-приложение для записи на занятия к репетиторам. Проект включает REST API на Spring Boot, PostgreSQL и веб-интерфейс на HTML/CSS, который раздаётся через Nginx.

## Возможности

- регистрация и авторизация пользователей (JWT, пароли хранятся в виде хэша BCrypt);
- три роли: ученик, репетитор и администратор;
- каталог репетиторов с поиском по предметам и фильтрами по цене, рейтингу и опыту;
- карточки репетиторов: фото, описание, предметы, цена за час, рейтинг;
- свободные временные слоты, рассчитываемые по графику репетитора, выходным и уже существующим записям;
- запись на занятие любой длительности из списка (30, 45, 60, 90, 120 минут) и бесплатное вводное занятие;
- подтверждение или отклонение заявок репетитором, отмена записи;
- защита от двойного бронирования: блокировка строки репетитора в транзакции (`SELECT ... FOR UPDATE`) и ограничения PostgreSQL на пересечение интервалов; при конфликте API возвращает `409 Conflict`;
- личный кабинет ученика: личные данные, вкладки «Предстоящие» и «Прошлые» занятия, домашние задания, оценки;
- кабинет репетитора: занятия на сегодня и по датам, заявки учеников с рейтингом, управление предметами и ценами, рабочие часы и выходные;
- панель администратора: статистика, пользователи и роли, справочник предметов, репетиторы, общее расписание;
- автоматическая плановая задача: прошедшие подтверждённые занятия становятся «проведёнными», неотвеченные заявки отклоняются;
- API-документация Swagger UI.

## Роли

| Роль | Возможности |
|---|---|
| Гость | просмотр каталога, поиск и фильтры, свободные слоты |
| Ученик | запись и отмена занятий, личный кабинет, оценка проведённых занятий |
| Репетитор | профиль, предметы и цены, график и выходные, занятия, принятие и отклонение заявок, домашние задания, оценка учеников |
| Администратор | статистика, пользователи и роли, справочник предметов, репетиторы, общее расписание, отмена любых записей |

## Технологии

- **Backend:** Java 21, Spring Boot 4, Spring Security (JWT), Spring Data JPA, Flyway, Gradle;
- **База данных:** PostgreSQL 16;
- **Frontend:** HTML, CSS;
- **Веб-сервер frontend:** Nginx;
- **Запуск:** Docker Compose;
- **Тесты:** JUnit 5, Mockito, Testcontainers.

## Требования

Для запуска всего проекта:

- Docker Desktop или Docker Engine с поддержкой Docker Compose;
- Git (если проект клонируется из репозитория).

Для запуска backend без Docker дополнительно нужны JDK 21 и PostgreSQL.

## Запуск проекта через Docker Compose

### 1. Получить проект

Клонируйте репозиторий или откройте папку проекта:

```bash
git clone <URL-репозитория>
cd tutoring-service
```

Если проект уже скачан, перейдите в его корневую папку, туда, где находится `docker-compose.yml`.

### 2. Подготовить переменные окружения

Создайте файл `.env` на основе примера:

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

В `.env` заданы параметры подключения к PostgreSQL и секрет JWT. Для локального запуска можно использовать значения из примера.

> **Важно:** `JWT_SECRET` должен быть не короче **32 символов**. При более коротком значении backend не запустится (ошибка `WeakKeyException`).

Не используйте демонстрационные значения в production и не публикуйте `.env`.

### 3. Запустить сервисы

Из корневой папки проекта выполните:

```bash
docker compose up --build -d
```

Команда запустит:

| Сервис | Адрес |
|---|---|
| Frontend | http://localhost:3000 |
| Backend API | http://localhost:8080 |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |
| Health check | http://localhost:8080/actuator/health |
| PostgreSQL | `localhost:5432` (доступен только локально) |

Backend запускается после того, как PostgreSQL станет доступен. При первом старте Flyway создаёт структуру базы данных. В профиле `demo` также добавляются демонстрационные данные, если база ещё пуста.

### 4. Проверить состояние сервисов

```bash
docker compose ps
```

Посмотреть логи backend:

```bash
docker compose logs -f backend
```

Логи всех сервисов:

```bash
docker compose logs -f
```

## Проверка работы

1. Откройте frontend: http://localhost:3000.
2. Проверьте доступность API: http://localhost:8080/actuator/health. При успешном запуске ответ содержит статус `UP`.
3. Откройте Swagger UI: http://localhost:8080/swagger-ui/index.html. Там можно просматривать и вызывать API-методы. Для защищённых методов войдите через `POST /api/auth/login`, скопируйте токен и нажмите **Authorize**.
4. Для проверки авторизации используйте один из демонстрационных аккаунтов ниже.

## Сценарий бронирования

Сценарий можно пройти в Swagger UI или через curl. Ниже вариант для bash:

```bash
# 1. вход ученика
TOKEN=$(curl -s localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"student@demo.com","password":"Student123!"}' | jq -r .token)

# 2. каталог: предметы и репетиторы (поиск, фильтры, сортировка)
curl -s localhost:8080/api/subjects
curl -s 'localhost:8080/api/tutors?subjectId=1&maxPrice=2000&sort=popular'

# 3. свободные слоты репетитора на дату (будний день в будущем)
curl -s 'localhost:8080/api/tutors/1/slots?subjectId=1&durationMinutes=60&date=2026-11-16'

# 4. запись на выбранный слот (startTime берётся из ответа со слотами); статус PENDING
curl -s localhost:8080/api/bookings -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"tutorId":1,"subjectId":1,"startTime":"2026-11-16T07:00:00Z","durationMinutes":60,"intro":false}'

# 5. повторная запись на то же время (в том числе от другого ученика) возвращает 409 SLOT_TAKEN,
#    слот исчез из списка слотов (повторить п. 3)

# 6. репетитор принимает заявку
TUTOR=$(curl -s localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"tutor1@demo.com","password":"Tutor123!"}' | jq -r .token)
curl -s localhost:8080/api/tutor/requests -H "Authorization: Bearer $TUTOR"
curl -s -X POST localhost:8080/api/tutor/bookings/<id>/accept -H "Authorization: Bearer $TUTOR"

# 7. ученик видит занятие в кабинете, затем отменяет его (слот освобождается)
curl -s localhost:8080/api/bookings/my/upcoming -H "Authorization: Bearer $TOKEN"
curl -s -X POST localhost:8080/api/bookings/<id>/cancel -H "Authorization: Bearer $TOKEN"

# 8. права доступа: ученик на /api/admin/** получает 403, запрос без токена получает 401
```

Жизненный цикл записи:

```text
PENDING ──принял репетитор──▶ CONFIRMED ──занятие прошло (автоматически)──▶ COMPLETED
   │                              │
   ├─ отказ / время начала прошло ▶ REJECTED
   └──── отмена учеником, репетитором или администратором ──▶ CANCELLED
```

Слот занят в статусах `PENDING`, `CONFIRMED` и `COMPLETED`. Статусы `REJECTED` и `CANCELLED` освобождают слот. Отмена подтверждённой записи учеником возможна не позднее чем за 2 часа до начала, администратор может отменить в любой момент.

## Локальный запуск backend

Этот вариант подходит для разработки, если PostgreSQL запущен отдельно.

1. Установите JDK 21 и запустите PostgreSQL (например, `docker compose up -d db`).
2. Создайте базу данных и пользователя либо используйте значения из `.env`.
3. Задайте секрет JWT (не короче 32 символов). В IntelliJ IDEA: **Run → Edit Configurations → Environment variables**:

   ```text
   JWT_SECRET=local-dev-secret-local-dev-secret-0123456789
   ```

4. Перейдите в папку backend и запустите приложение:

   **Windows PowerShell:**

   ```powershell
   cd backend\tutoring-backend
   $env:JWT_SECRET = "local-dev-secret-local-dev-secret-0123456789"
   .\gradlew.bat bootRun
   ```

   **Linux / macOS:**

   ```bash
   cd backend/tutoring-backend
   JWT_SECRET=local-dev-secret-local-dev-secret-0123456789 ./gradlew bootRun
   ```

Чтобы включить демо-данные при локальном запуске, активируйте профиль `demo`.

**PowerShell:**

```powershell
$env:SPRING_PROFILES_ACTIVE = "demo"
.\gradlew.bat bootRun
```

**Linux / macOS:**

```bash
SPRING_PROFILES_ACTIVE=demo ./gradlew bootRun
```

Параметры базы можно переопределить переменными окружения `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` и `SPRING_DATASOURCE_PASSWORD`.

Frontend при Docker-запуске доступен через Nginx на порту `3000`. При локальном запуске backend отдельно откройте HTML-файлы из папки `frontend` через локальный веб-сервер, чтобы избежать проблем с браузерными ограничениями.

## Запуск тестов

Тесты backend запускаются Gradle. Интеграционные тесты используют Testcontainers, поэтому для них должен быть запущен Docker.

**Windows PowerShell:**

```powershell
cd backend\tutoring-backend
.\gradlew.bat test
```

**Linux / macOS:**

```bash
cd backend/tutoring-backend
./gradlew test
```

Отдельный тестовый класс или метод:

```bash
./gradlew test --tests "*BookingConcurrencyIT"
./gradlew test --tests "*BookingApiIT.sameSlotIsRejected"
```

HTML-отчёт: `backend/tutoring-backend/build/reports/tests/test/index.html`.

### Проверка работающего API (скрипт)

Скрипт проходит по всему API: регистрация и вход, каталог и фильтры, слоты, полный цикл записи, валидация, права доступа, кабинет репетитора, админ-панель и три сценария одновременной записи (один слот, пересекающиеся интервалы, один ученик к двум репетиторам). Нужен запущенный backend с профилем `demo` и пустая демо-база.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\api-check.ps1
```

Параметры (адрес backend и число параллельных запросов):

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\api-check.ps1 -Base "http://localhost:8080" -Racers 8
```

Код возврата: `0`, если все проверки пройдены, `1`, если есть ошибки, `2`, если скрипт не смог запуститься (backend недоступен, нет демо-аккаунтов). Скрипт создаёт тестовых пользователей `chk_...` и `race_...`, для чистой базы выполните `docker compose down -v`.

Скрипт рассчитан на демо-данные: репетиторы Анна Смирнова и Дмитрий Орлов (пн-пт 09:00-18:00, общий предмет «Математика») не должны менять график и предметы.
