# Объединение Frontend и Backend

## Обновление существующей папки проекта

1. Остановите текущие контейнеры (данные БД при этом сохраняются):

   ```powershell
   docker compose down
   ```

2. Распакуйте архив `tutoring-service-integration-patch.zip` непосредственно в корневую папку проекта, например `C:\projects\tutoring-service-main`, подтвердив замену файлов.
3. Не удаляйте существующий `.env`.
4. Запустите проект:

   ```powershell
   docker compose up --build -d
   ```

5. Проверьте контейнеры и логи:

   ```powershell
   docker compose ps
   docker compose logs --tail=100 backend
   docker compose logs --tail=100 frontend
   ```

6. Откройте `http://localhost:3000`.

## Как теперь проходят запросы

Браузер обращается к одному адресу — `http://localhost:3000`. Nginx отдаёт HTML/CSS/JavaScript, а все запросы с префиксом `/api/` проксирует во внутренний Docker-сервис `backend:8080`. Frontend не обращается к PostgreSQL напрямую: база доступна только backend.

JWT-токен после входа хранится в браузере и передаётся серверу в заголовке `Authorization: Bearer ...`.

## Подключённые сценарии

- Каталог предметов и репетиторов, серверные фильтры по цене, рейтингу, опыту и предмету.
- Вход по e-mail и паролю, регистрация ученика, переход в кабинет по роли.
- Получение доступных слотов из backend, создание реальной записи, бесплатное вводное занятие длительностью 30 минут.
- Кабинет ученика: профиль, предстоящие и прошлые занятия, отмена записи, оценка проведённого занятия.
- Кабинет репетитора: профиль, занятия и заявки, принятие/отклонение, домашнее задание, оценка ученика, цены и предметы, рабочий график с несколькими интервалами в день.
- Кабинет администратора: статистика, поиск и блокировка пользователей, создание и активация профилей репетиторов, справочник предметов, общее расписание и отмена записи.

## Тестовые учётные записи

Используйте демонстрационные аккаунты из раздела «Демо-аккаунты» файла `README.md`. Вход выполняется по e-mail, а не по имени пользователя.

Публичная регистрация в текущем backend создаёт ученика. Профиль репетитора создаётся администратором из существующего пользователя; после этого репетитор входит под своим e-mail и паролем.

## Что пока не подключено

В backend отсутствуют соответствующие API-методы, поэтому интерфейс не имитирует эти операции через `localStorage`:

- отправка и модерация жалоб;
- загрузка и постоянное хранение фотографий;
- отдельный реестр образования/сертификатов репетитора.

Токен и краткие данные текущего пользователя сохраняются в `localStorage` только для поддержания авторизации. Рабочие данные каталога, расписания, пользователей и бронирований приходят из backend.
